# Phase 10 — Image library curation + calibration

This is the operator playbook for the bulk work in Phase 10 of the
autonomous-navigation rewrite (`AUTONAV_PLAN.md`):

1. **Source ~50 images** that together exercise every scene class and
   every non-deferred `NavTechnique`.
2. **Manually navigate each one** to produce an operator-verified
   ground-truth offset.
3. **Save a sidecar** in the right scene-class directory.
4. **Run the autonomous pipeline** on the resulting library and seed a
   regression baseline per image.
5. **Calibrate** each technique's confidence formula against the
   library's `confidence_tier` targets (and replace every `PLACEHOLDER`
   in `config_510_techniques.yaml`).

The reference for the schema / scene classes / coverage matrix is
`docs/dev_guide/dev_guide_image_library.rst` plus `AUTONAV_PLAN.md`
Part 10.
This file is the *workflow* — what to do in what order, where the
data lives, how the manual-nav UI threads into it, and how a
hand-picked offset eventually turns into a passing CI test.

This document is ephemeral: once the library is built and the
calibration sweep has landed, Phase 10 is over and this file should
be deleted.

---

## What you are producing

For each library image, three artefacts are required, in this order:

1. **Sidecar** at:

   ```
   tests/integration/image_library/images/<scene_class>/<image_id>.yaml
   ```

   Carries: mission/camera/filter, `pds3://` URL, ground-truth offset
   + 1σ uncertainty, expected `status`, `confidence_tier`, and primary
   technique.  Schema validated by `tests.integration.sidecar`.

2. **Regression baseline** at:

   ```
   tests/integration/baselines/<image_id>.json
   ```

   Three rounded scalars: `offset_dv_px`, `offset_du_px`, `confidence`.
   Generated by running the autonomous orchestrator on the image and
   snapshotting its output.  Schema in `tests.integration.baseline`.

3. **(Eventual)** the calibrated coefficients in
   `src/nav/config_files/config_510_techniques.yaml` produced by
   fitting confidence formulas against the per-tier targets across the
   library.  This is one PR after the library is full.

The directory tree under `tests/integration/image_library/images/`
**is** the registry — there is no `manifest.yaml`.  Adding a sidecar
in the right scene-class subdirectory enrolls the image automatically.

## Per-class selection guide

The table below tells you what to look for, what to avoid, and which
mission archives are most likely to contain a clean example.  When a
candidate sits between two classes, pick the one that exercises the
*expected primary technique* and document the judgment in the sidecar
`notes`.

| Class                          | Geometric requirement                                                            | Mission spread (target ≥1 per row)                                                    | Common gotchas (avoid these)                                  |
|--------------------------------|----------------------------------------------------------------------------------|---------------------------------------------------------------------------------------|---------------------------------------------------------------|
| `star_dominated`               | ≥3 catalog stars predicted detectable in extfov; no body silhouette              | **Cassini ISS** NAC star-cal frames (Pleiades, Vega); **NHLORRI** approach-cruise     | Smear > 30 px; saturated bloom across frame                   |
| `body_full_fov`                | Regular body ≥ 70 % of FOV; full limb in frame; ≥30 % lit                        | **Cassini ISS** NAC mid-range satellites; **Galileo SSI** Galilean flybys; **NHLORRI** Pluto/Charon | Crescent > 50 % terminator (use `high_phase_terminator`)      |
| `body_partial_overflow`        | Body 70–90 % in frame; visible limb arc > 30 %                                   | Cassini close encounters (Mimas, Enceladus); Galileo flybys                           | <50 % in-frame (use `body_mostly_offscreen`)                  |
| `body_mostly_offscreen`        | Body 50–90 % off-frame; limb arc ≥10 % visible                                   | Cassini closest-approach NAC; Galileo close flybys (Io, Europa)                       | No limb at all in FOV (use `negative_cases`)                  |
| `body_irregular`               | Irregular body where `limb_uncertainty_px > 3` (BLOB regime)                     | Cassini Phoebe / Hyperion / small inner moons                                         | Body so close BLOB centroid is also ambiguous                 |
| `multi_body`                   | ≥2 separable bodies in FOV; not occluding                                        | Cassini Saturn-system family portraits; Galileo Jupiter-system multi-moon shots       | Bodies overlapping (occlusion is tested separately)           |
| `ring_only_curved`             | Polyline max-deviation > 0.5 px from straight; no bodies                         | Cassini Saturn rings, mid-range                                                       | Bodies in FOV (use `ring_plus_body`)                          |
| `ring_only_flat`               | Ring-edge polyline curvature < 0.5 px                                            | Cassini Saturn ansa shots; long-range ring-only frames                                | Curved enough to hit full-rank (defeats rank-1 test)          |
| `ring_plus_body`               | Rings + ≥1 moon in FOV                                                           | Cassini Saturn + ring-shepherd moons                                                  | Edge-on rings + body (harder to characterize)                 |
| `stars_plus_body`              | Body + ≥3 visible stars                                                          | Cassini, NHLORRI long-exposure background-stars frames                                | Accidentally also `multi_body` — check before saving          |
| `one_bright_star_no_body`      | Catalog yields exactly 1 unambiguous star (next-brightest ≥ 1.5 mag fainter)     | Cassini ISS + NHLORRI star-cal frames                                                 | Next-brightest within 1.5 mag — use `two_bright_stars_no_body` |
| `two_bright_stars_no_body`     | Catalog yields exactly 2 unambiguous stars; no body, no rings                    | Cassini ISS + NHLORRI star-cal frames                                                 | Saturated/faint pair → assignment ambiguous                   |
| `faint_stars`                  | Predicted SNR < 3.0 for every catalog star in FOV                                | **Galileo SSI** science frames; **Voyager ISS** outer-leg                             | Accidentally clean frame where stars do show                  |
| `scattered_light`              | Galileo SSI / Voyager ISS frame with visible stray-light gradient                | Galileo Earth/Moon outer fields; Voyager Saturn-encounter outer-leg                   | Already-flat frame (not a real example)                       |
| `high_phase_terminator`        | Crescent body, phase > 90°                                                       | Cassini ISS approach phase (Saturn moons); Galileo Earth-departure crescent           | Crescent so thin no terminator pixels rise above noise        |
| `below_resolution_body`        | Body diameter < 15 px (any mission, distant body)                                | Voyager / Cassini long-range satellite frames                                         | Body so distant BLOB centroid is sub-noise (use `negative_cases`) |
| `negative_cases`               | Unnavigable: distant tiny body + sensor-limited stars; empty interplanetary      | Spread across all four missions                                                       | Scene that *barely* navigates (use `low` tier instead of `failed`) |

### Mission-specific hints

Per `AUTONAV_PLAN.md` Part 1 §"Star-poor missions":

- **Cassini ISS (NAC + WAC):** rich source of every body / ring class
  *and* the most usable star fields.  Both `_RAW.IMG` and `_CALIB.IMG`
  versions exist; mark the suffix in `image_id` so the loader picks the
  right config block (`cassini_iss` vs `cassini_iss_calib`).  The CALIB
  variant exercises the `signal_dn_to_image_unit_scale` path added in
  Phase 10 §F; **at least one calibrated CISS image must be in the
  library** so the calibration sweep covers that path.  **Saturation
  policy:** the saturation gate is intentionally off for calibrated_if
  (a single I/F threshold cannot identify saturated DN — the CALIB
  pipeline applies an exposure-/filter-/gain-dependent scale).
  Whenever accurate saturation flags matter for a Cassini frame
  (e.g. a textbook Pleiades star-cal where bright stars saturate),
  curate the matching `_RAW.IMG` instead — Cassini calibration is not
  geometric, so raw and calibrated share pixel coordinates and the
  ground-truth offset is the same.
- **NHLORRI:** strong star-cal coverage (panchromatic; one filter slot,
  encoded `1`).  Pluto / Charon for body classes.  Currently `raw_dn`
  only — no calibrated variant in the per-instrument config.
- **Galileo SSI:** the canonical source of `faint_stars` and
  `scattered_light`; carries non-trivial camera-rotation residuals
  (`fit_camera_rotation: true` in `config_410_inst_gossi.yaml`).  Use
  for body classes too where appropriate.
- **Voyager ISS:** the second source of `faint_stars` and
  `scattered_light`; the outer-leg frames are the textbook stray-light
  cases.  Also `fit_camera_rotation: true`.  Voyager **must** be
  navigated against the calibrated (geometrically corrected) frames
  because raw Voyager frames carry uncorrected geometric distortion;
  when a `voyager_iss_calib` block is added, the same saturation-off
  policy as Cassini CALIB will apply (Phase 10 §F).  Bright-star
  saturation on Voyager calibrated frames is invisible to the
  reliability gate under that policy; this is a known limitation
  worked around by the matched-filter peak shape + post-fit residual
  checks.  In practice Voyager science frames have so few unsaturated
  bright stars that this is a non-issue for the library.

Aim for *all four missions* across the full library so the calibration
sweep does not silently overfit one camera's behaviour.

## Workflow per image

### A. Source the candidate

Identify a candidate `image_id` (e.g. `W1521598221_1_CALIB`) and the
`pds3://` URL of the file.  Make sure the holdings cache resolves it:

```bash
export PDS3_HOLDINGS_DIR=https://pds-rings.seti.org/holdings
# or a local mirror if you have one
```

### B. Open it in manual-nav

Run:

```bash
nav_offset [args] --manual
```

where `[args]` are whatever selection / dataset / config flags pin
the run down to a single image (e.g. the dataset id, an image-list
file, ``--config`` for a non-default config bundle, ``--pds3-holdings-dir``
if the holdings cache lives somewhere non-standard).  The dialog
shows the SPICE-predicted body / ring / star overlay against the
image.  The selection must resolve to exactly one image — the flag
fails fast if it matches more than one.

The dialog bypasses the autonomous pipeline's reliability gate
(`apply_gate=False`) so calibrated CISS frames whose stars would
currently be gated out can still be navigated by hand.  This is the
intentional workaround for the predicted-SNR bug fixed in Phase 10 §F:
even with the fix in place the placeholder
`signal_dn_to_image_unit_scale` values are not yet calibrated, so
manual nav remains the source of ground truth.

### C. Pick the offset by hand

Drag the overlay until limbs / terminators / star centroids line up
at sub-pixel precision.  Or hit **Auto** and accept the pipeline's
proposal if it visibly nails it; for genuinely hard cases (faint stars,
scattered light) hand-tweak from there.

The convention (Part 0): the **predicted** position `(v, u)` plus the
chosen offset `(dv, du)` equals the **actual** position in the image.

### D. Save the sidecar

Click **Save as Library Entry...** in the dialog.  It produces a
`<image_id>.yaml` skeleton — point the file-save dialog at the
appropriate scene-class directory under
`tests/integration/image_library/images/<class>/`.  The dialog also
writes a companion `<image_id>.png` next to the YAML showing the
red-image / green-model overlay at the chosen `(dv, du)`; it is an
orientation aid for future reviewers (no test reads it).

Open the saved YAML and replace every `TODO_REPLACE_*` placeholder.

> **Important framing.** The `expected.*` fields are the **target**
> values you want the *fully calibrated* pipeline to produce, not a
> description of what the pipeline does today.  The calibration sweep
> in step C of this phase fits the α coefficients against exactly
> these targets; if you fudge them to match placeholder behaviour, you
> bake the placeholders into the curated truth and the sweep has
> nothing left to fix.  Initial-library `test_autonomous_nav.py`
> failures on the tier check are *expected* and informational — they
> are the calibration input.

Field rubric:

- `scene_tags` — first entry must equal the directory name; add a
  body / morphology tag as the second.
- `filter_combo` — sorted, `+`-joined (e.g. `CL1+CL2`).  Same
  canonicalization the per-camera `mag_offset_table` uses.
- `ground_truth.offset_uncertainty_px` — typically **1.0 px** for
  sharp limbs / bright stars; **2.0 px** for soft features or
  star-poor.  CI slack is `offset_uncertainty_px + 0.5 px`.
- `ground_truth.notes` — a one-line human-readable rationale; mention
  what feature you used to verify the alignment.
- `expected.status` —
  - `ok` for every navigable scene (the common case).
  - `failed` only inside the `negative_cases/` directory.  These are
    the scenes that must be unnavigable: distant tiny body + sensor-
    limited stars; empty interplanetary frame; majority-dropout image.
  - `conflicted` only when the scene is *designed* to make two
    disjoint ensembles disagree by more than their combined
    uncertainty.  Don't reach for this lightly; if you're unsure, the
    answer is `ok`.
- `expected.confidence_tier` — pick from the rubric below for the
  tier the **fully calibrated** pipeline ought to land, given how
  good the scene actually is.  This is the calibration target
  midpoint your sidecar contributes:
  - `high` — sharp limb fully in frame, dense bright stars, multiple
    unambiguous features.  Calibrated σ should be < 0.5 px.
  - `medium` — partial limb / soft terminator / a few stars but not
    many.  Calibrated σ ~ 0.5–1.5 px.
  - `low` — barely navigable: tiny body, faint stars, marginal SNR.
    Calibrated σ > 1.5 px but still clearly a fit.
  - `failed` — must pair with `status='failed'` (`negative_cases/`).
  - `conflicted` — must pair with `status='conflicted'`.

  **Ratchet conservatively.**  A `medium` that comes back `high`
  after calibration is a free win you can revise upward; a `high`
  that the calibrated pipeline can never reach is a target the fit
  cannot satisfy, which biases the α coefficients across every other
  image.  Practical rule: if you'd be unsurprised either way, write
  `medium`.

- `expected.primary_technique` — the technique you expect to win
  pass-1.  Cross-check against the coverage matrix in Part 10
  §"Coverage matrix".  Quick map:
  - body fills FOV → `BodyDiscCorrelateNav`
  - body partly off-frame, limb visible → `BodyLimbNav`
  - crescent (phase > 90°) → `BodyTerminatorNav`
  - close-in irregular body → `BodyBlobNav`
  - distant body < 15 px → `BodyBlobNav`
  - curved ring edge → `RingEdgeNav`
  - flat ring edge → `RingEdgeNav` (rank-1 mode) or `RingAnnulusNav`
  - ≥3 catalog stars → `StarFieldFromCatalogNav`
  - exactly 1 unambiguous star → `StarUniqueMatchNav`
  - exactly 2 unambiguous stars → `StarUniqueMatchNav`

  For ensemble scenes, pick the higher-confidence technique as
  primary.  Tie-break is `(−confidence, technique_name)` ascending,
  so when both produce comparable confidence the alphabetically
  earlier name wins.

- `expected.techniques_must_run` — the smallest non-trivial set you
  would defend.  Default to **just the primary** for now.  Adding
  more here means each addition is an independent regression-failure
  mode — only list a technique if the scene clearly enables it (limb
  + correlate on a 70 % body, two ring edges + a moon).  Don't list
  techniques that *might* run.

- `expected.techniques_must_skip` — assert *infeasibility*: the
  technique truly cannot produce a result on this scene.  Examples:
  - `body_full_fov` → `[StarFieldFromCatalogNav]` (no stars in FOV)
  - `one_bright_star_no_body` → `[BodyLimbNav, BodyDiscCorrelateNav]`
  - `ring_only_curved` → `[BodyLimbNav]`
  - `negative_cases` → typically empty (everything skipped)

  Don't list techniques that just happen to be low-confidence; only
  list ones the feasibility gate should reject outright.

### E. Validate the schema

Run the structural-invariants test in plain (no holdings) mode:

```bash
pytest tests/integration/test_image_library.py -m "" -k <image_id>
```

Iterate until it passes.  This catches typos in scene-class names,
duplicate `image_id`s, malformed enums, conflicting `status` /
`confidence_tier` combinations, and overlap between
`techniques_must_run` and `techniques_must_skip`.

### F. Run the autonomous pipeline

With `PDS3_HOLDINGS_DIR`, `OOPS_RESOURCES`, `UCAC4_PATH`, `YBSC_PATH`,
and `SPICE_PATH` set:

```bash
pytest tests/integration/test_autonomous_nav.py -m "" -k <image_id>
```

It will probably fail the first time you run it — that is expected
during Phase 10.  The reasons (and what to do about them) are in
*"Why does the test fail when I have a manual offset"* below.

### G. Seed the regression baseline

Once the autonomous result is within tolerance and lands the right
tier, write the baseline JSON.  Use the developer tool at
`tests/integration/update_baselines.py` (intentionally not packaged
as a user CLI — invoke as a Python module from a project checkout):

```bash
python -m tests.integration.update_baselines --image-id <image_id>           # one image
python -m tests.integration.update_baselines --image-id A --image-id B       # batch
python -m tests.integration.update_baselines --all                           # every sidecar
python -m tests.integration.update_baselines --all --dry-run                 # preview only
```

The tool runs the autonomous orchestrator, rounds the result via
`Baseline.from_run` (`offset` to 4 decimals, `confidence` to 3), and
writes `tests/integration/baselines/<image_id>.json`.  Each image is
reported as `CREATE`, `UPDATE` (with a per-field diff), `UNCHANGED`,
or `FAILED`.  Requires `PDS3_HOLDINGS_DIR`.

The on-disk schema is:

```json
{
  "confidence": 0.871,
  "image_id": "W1521598221_1_CALIB",
  "offset_du_px": -130.9985,
  "offset_dv_px": 299.0010
}
```

Comparison at test time is exact-equal on the rounded values; the
PR review must include the regenerated JSON files in the same diff
as whatever change caused the baseline to move.

## Why does the test fail when I have a manual offset?

This is the central confusion the rest of Phase 10 resolves.  Three
distinct comparisons are happening:

1. `test_image_library.py` — purely structural.  Doesn't touch
   holdings.  It just validates the YAML.  Should pass as soon as the
   sidecar is well-formed.

2. `test_autonomous_nav.py` — runs the live orchestrator and compares
   against the sidecar's `ground_truth.offset_*` and
   `expected.confidence_tier` / `status` / `primary_technique`.  The
   manual-nav offset is the *target*; the autonomous pipeline is the
   *system under test*.  This test fails whenever the pipeline can't
   reproduce the operator's offset within `offset_uncertainty_px + 0.5
   px` slack, *or* lands the wrong tier, *or* runs/skips a technique
   that violates the must_run / must_skip list.

3. `test_baselines.py` — exact-equal regression on the rounded
   `(offset_dv_px, offset_du_px, confidence)` triple, byte-identical
   given the same code + same static-data hashes.  Used as a tripwire
   against unintended algorithmic drift between PRs.

So having a hand-picked offset is *necessary but not sufficient* for
the test to pass.  The pipeline still has to reproduce that offset.
Tests 2 and 3 only pass once **both** of these are true:

- The pipeline's autonomous run lands within tolerance of the
  ground-truth.
- The confidence-formula coefficients in
  `config_510_techniques.yaml` map the run's diagnostic numbers onto
  the right tier.

Until the calibration in Phase 10 item C runs, the second condition is
the one that gets violated for the majority of images: the *placeholder*
α coefficients live in `config_510_techniques.yaml` and assign
arbitrary tiers.  The expectation is therefore that during library
expansion, `test_autonomous_nav.py` tier checks are *informational* —
add the sidecar with your best-judgement tier, expect failures, and
collect them all.  After all 49 sidecars are in, run the calibration
sweep and the tiers should align.

## How do we get the confidence + calibration data?

Per `AUTONAV_PLAN.md` Part 10 §"Confidence calibration", the formula
for every technique is:

```
confidence = sigmoid(α₀ + Σ αᵢ × xᵢ)
```

where `xᵢ` are the diagnostics each technique reports (e.g. for a star
refine: number of inliers, residual scatter, at-edge flag).  Phase 10
calibrates the `αᵢ` once against the curated library:

1. **Per image, per technique**, the orchestrator already records every
   `xᵢ` it consumed when computing the placeholder confidence (the
   diagnostics live on the per-technique result and are echoed in the
   `_metadata.json` log file).
2. **The sidecar's expected tier** maps onto a numeric **target
   midpoint**:

   ```
   target = {high: 0.9, medium: 0.65, low: 0.35, failed: 0.1}[tier]
   ```

3. **Across the library**, a one-shot `scipy.optimize.curve_fit` finds
   the α vector minimizing the squared error between
   `sigmoid(α₀ + Σ αᵢ xᵢ)` and `target`, with one fit per technique
   (each technique has its own diagnostic vector).
4. **Replace the placeholder coefficients** in
   `config_510_techniques.yaml` with the fitted values.  The PR review
   gate enforces that no `PLACEHOLDER` markers ship to production
   (Part 0 §5).
5. **Audit per-instrument residuals.**  After the fit, dump the
   residual `tier_target − sigmoid(α·x)` for every library image and
   bucket by `sidecar.mission`.  If one mission's residual
   distribution is systematically off (mean magnitude > ~0.1 in
   tier-space, or visibly asymmetric vs the others), the unified
   one-α-per-technique assumption is failing for that camera.  Two
   responses, in order of preference:
   - Find the offending diagnostic and add a per-instrument scale
     upstream (the `signal_dn_to_image_unit_scale` pattern from
     Phase 10 §F — keep the formula global, fix the inputs).
   - If no single diagnostic is the culprit, promote the schema to
     per-instrument α vectors
     (`techniques.<name>.<instrument>.{...}` with a fallback default
     block).  This is the heavier change and should only land if (1)
     leaves the residuals unbalanced.

   Either decision belongs in the same PR as the calibration sweep so
   the rationale and the per-mission residual plot are reviewed
   together.
6. **Re-run** `test_autonomous_nav.py` against the full library; the
   tier checks should now match (any image whose tier is still wrong
   means the human-assigned tier was outside what the diagnostics could
   distinguish; revisit *that* sidecar's tier).

The fit is one-time.  After it lands,
`config_510_techniques.yaml` is frozen, baselines are seeded, and the
library exists as the regression-protection net for every subsequent
change.

The `ground_truth.offset_*` is **not** an input to the fit — it is
what the orchestrator's *position* claim is checked against.  Tier
calibration is a separate, parallel operation that consumes the
`expected.confidence_tier` labels.

## Concrete next steps for the operator

The current state of the library (as of 2026-04-30):

- 11 sidecars across 9 of 17 scene classes.
- 1 baseline JSON (`N1597846115_2_CALIB.json`).
- 11 of ~55 bodies populated in `config_220_body_shape.yaml` (all
  PLACEHOLDER values awaiting Phase 10 §B literature population).

**Recommended order of work:**

1. **Fill the missing scene-class directories first.**  Add at least
   one image per class for the eight currently empty classes:
   `body_full_fov` (1 of 3 done), `body_irregular` (0 of 3),
   `body_partial_overflow` (1 of 3 done), `faint_stars` (0 of 2),
   `high_phase_terminator` (1 of 2 done), `multi_body` (1 of 3 done),
   `negative_cases` (0 of 3), `ring_only_flat` (0 of 3), `ring_plus_body`
   (0 of 3), `scattered_light` (0 of 2), `stars_plus_body` (0 of 3),
   `two_bright_stars_no_body` (0 of 2).

2. **Top up to the per-class minima.**  The structural-invariants test
   asserts each non-empty class has at least the Part 10 minimum count;
   this catches accidental overfit to a single example.

3. **Verify mission spread.**  Aim for ≥1 Cassini ISS + ≥1 Galileo SSI
   + ≥1 NHLORRI + ≥1 Voyager ISS across the full set, and ≥1 `_CALIB`
   Cassini frame so the `signal_dn_to_image_unit_scale` path
   (Phase 10 §F) is exercised.

4. **Submit in batches of 5–10 sidecars per PR.**  Reviewer cost on a
   curation PR is dominated by `ground_truth` spot-checks; smaller PRs
   review faster and surface schema mistakes earlier.

5. **After ~50 sidecars are in**, run the confidence-formula
   calibration sweep (Phase 10 §C) as its own PR.  That is when the
   `test_autonomous_nav.py` tier checks are expected to start passing
   uniformly.

6. **Seed regression baselines** as the final library PR (Phase 10 §D).
   At that point the library is read-only except for additive sidecars
   when new scene classes emerge.
